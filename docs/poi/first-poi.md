in a vanilla interior cell, in a new plugin whose only master is `Starfield.esm`. Built,
validated and planned by agents (lane E, M4.E2/E3/E4/E6); the in-game check is the owner's
(M4.O2), on the MO2 profile **KitKraft Dev** with a disposable save, never `Default`.

Reproduce (the game's Data folder is detected; `kit doctor` shows it):

```text

kit roundtrip out/poi/KitKraftFirstPOI.esm --verify
kit inspect KitKraftFirstPOI.esm:001000 --plugins Starfield.esm --plugins out/poi/KitKraftFirstPOI.esm
kit testplan out/poi/KitKraftFirstPOI.esm out/poi/testplan --profile "<MO2>\profiles\Kitkraft Dev" --from-save newest --spec docs/poi/first-poi.toml
kit package out/poi/KitKraftFirstPOI.esm out/poi/package --spec docs/poi/first-poi.toml
```

Results (2026-10-14, release build): two builds give the same bytes; `validate` passes with
0 errors and 0 warnings on all 14 rules (the cell rules included); `roundtrip --verify` is
identical (3 records, 5 groups); `inspect` with the plugin appended finds the reference with
one version and runtime ID `01001000` on that two-plugin order. The group path is `CELL`
top > block 9 > sub-block 9 > cell children > persistent children (type 8), the `HEDR` next
object ID is `FF001001`, and `INCC` is 1. Every member written is at `corpus` confidence
(`NAME`, `DATA` position and rotation from the world family's `REFR` definition, `EDID` and
the persistent flag from lane A's corpus tests). The record header's stamps are not corpus
defaults: form version 582 is the newest in the corpus, but timestamp, version control and
unknown 0 is rare or unobserved there (unknown is never 0 in several official files and
rarely elsewhere); what they mean is unknown, pending the CK's observation (F20).

### Setup

1. Install the plugin into MO2 as its own mod (`kit package`, then install the folder or zip;
   or `kit deploy --dev`), and enable it in the **KitKraft Dev** profile, after its masters.
2. Check the plugin's SHA-256 on disk equals the one above.
3. Copy `kitkraft-test.txt` into the folder that holds `Starfield.exe` (the game reads batch files
   from there: grade D, confirm it in this session).
4. Start Starfield through MO2 with the **KitKraft Dev** profile and load a disposable save
   (or start a new game and save it as one).

### Steps

Run all at once with `bat kitkraft-test` in the console, or type the commands one by one.

How to name an object: a reference with an EditorID is named by it (`player.moveto <EditorID>`,
`prid <EditorID>`; that the console takes a persistent reference's EditorID is grade D until
M4.O2). To read any object's ID, open the console and click the object: the console shows its
reference ID, whose high byte is the plugin's runtime slot. The numeric IDs below are
confirmed by the save Exitsave0_F5E3CCE2M546564_000052_20261015205905_1_0_4.sfs (game 1.16.244.0).

1. `coc CityNewAtlantisApartmentTEMPLATE` (cell Starfield.esm:21966F).
2. `player.moveto KitKraftFirstPOICrate`: you stand at the new REFR `KitKraftFirstPOICrate`.
3. Open the console and click the object: Crate_MilitarySupply_01 (STAT, Starfield.esm:1E4FBD) at (-17.0, -4.0, 4.6).
   **Expect:** the console shows the reference ID `04001000` (confirmed-by-save). Another ID means
   another slot, not a missing object: write down the ID shown.
4. `prid KitKraftFirstPOICrate`, then `getpos x`, `getpos y`, `getpos z`.
   **Expect:** `prid` selects the same object; the positions match (-17.0, -4.0, 4.6). Screenshot it
   (into `observe\`).
   Also `prid 04001000` (the numeric ID, confirmed-by-save): it selects the same object.

### Persistence

5. Leave the area (`coc` to another cell, or fast travel), wait one in-game hour (`wait`),
   save (a new disposable save), quit to the main menu, and load that save.
6. Return (`bat kitkraft-test` again). **Expect:** every object is where it was; note any that
   vanished, moved or doubled (a temporary reference may reset when its cell resets: say how
   long you were away).

### Report

Add an entry to `docs/game-observations.md`, id `game-<yyyymmdd>-<nn>`: game build, the
plugin's SHA-256 above, profile **KitKraft Dev**, each step with what was expected and what was
seen, and the screenshots' file names in `observe\`. A step that could not run (a batch file
the game did not read, a command it rejected) is a result: write it down.

### Afterwards

The plugin owns forms: keep it enabled for saves made with it, or delete those saves.
Disable it in **KitKraft Dev** only between disposable saves.
