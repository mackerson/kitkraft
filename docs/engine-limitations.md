# Engine limitation register (M5.F1)

This register lists what the game, the Creation Kit, the official tools or the file format
are known not to do, or not to let KitKraft do. The owner's inventory asks for it in item
F2 (`docs/foothold/engineering-surface.md`). A runtime-need record under ADR 0008 §5
links to the row it rests on. Every row in "Observed" cites a test, a `docs/gaps.md` row
or a ledger entry. Anything without that evidence is in "Hypotheses" and is not yet a
limitation.

Seeded on 2026-10-16 at commit `5d03d01` from `docs/gaps.md`, `docs/design/persistence.md`
(PS claims), `docs/game-observations.md`, ADR 0008, `plan/execution-plan.md` (M4 "Cannot"
and "Not in M4") and `docs/oracles.md`. Unless a row says otherwise, the build is game
1.16.244.0 and CK 1.16.244.0 (`docs/compatibility.md`). Add a row only with its evidence.
Close a row with the commit, test or ledger entry that lifts it, and keep the row,
struck through, as `docs/gaps.md` does.

Kinds:

- **engine**: the running game behaves so.
- **CK-only**: data only the Creation Kit computes.
- **official tool**: Bethesda's compiler or Archive2 behaves so, run as a black box.
- **format**: the file layout cannot be expressed or typed yet.
- **scope**: KitKraft refuses on purpose until evidence exists.

Hook column (ADR 0008 §5): "not justified" means §5 rules a runtime component out. "none
proposed" means no runtime-need record exists. A hook is never proposed from this register
alone.

## How to add a row

1. Run the experiment. Keep its evidence: a test, a ledger entry with the inputs' hashes,
   or a `docs/gaps.md` row with its command.
2. Fill every column. "Observed failure" is what was seen, and "Exact behaviour" names the
   API, CK step, file field or tool version.
3. If the row may justify a runtime component, write the runtime-need record
   (`docs/design/runtime-extensions.md`, created with the first record, ADR 0008 §5). Link
   the record to the row and the row to the record.
