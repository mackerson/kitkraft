# Register of explained non-conformities

Every place where KitKraft's output is known to differ from what the Creation Kit (or the game)
writes or does, and the difference was **accepted as explained rather than fixed**. Kept so that
each one can be found again if it later turns out to be the root of a bug (owner, 2026-11-17,
verbatim: "we need a register for any of these explained non-conformities later in case they
turn out to be bug roots").

**Rule: a new explained difference gets a row here in the same commit that accepts it**: a
`[[normalization]]` added to `docs/bench/ck-batch/explained-differences.toml` or to a fixture's
`fixture.toml`, a difference a `docs/ck-observations.md` or `docs/game-observations.md` entry
classes as explained, CK bookkeeping or an authoring choice. Ids are stable (`ENC-001` onward)
and never reused; a row whose explanation is withdrawn stays, marked withdrawn. A test
(`xtask/src/ckoracle.rs`, `every_rule_is_named_by_a_register_row`) fails when a rule of
`explained-differences.toml` has no row here naming it as `` `<record> <subrecord> <transform>` ``.

What a row holds: what differs (ours against the CK's); where (record and subrecord); how it
was explained and by whom (rule, ledger entry, owner ruling with its date); which evidence
passes rest on it (types with a `docs/schema/evidence.toml` `ck-differential-tested` pass that
needs it); what would go wrong if the explanation is false (the symptom to look for in the
game or the CK; **marked "inference"** where the records do not say it); how to re-check it;
and whether we could match the CK instead (with the ticket, if one exists). "Ledger" is
`docs/ck-observations.md`. Records only say what they say: nothing here is from the CK's code.

## The ten accepted oracle rules (`explained-differences.toml`)

Accepted by the owner on 2026-11-17, in chat, verbatim: "Accept all ten" (asked "Accept the ten
explained-difference rules?" after a table of all ten). Proposed by the triage of 2026-11-17
(`docs/bench/ck-batch/triage-20261117.md`, class B); each explains one subrecord and one exact
transformation, checked by `cargo xtask oracle ck --rules` on the decoded fields or payloads.
The passes were entered with the re-comparison `ck-20261117-65`.
